# docs Bugbot rules

If a PR adds a hand-authored doc under `docs/` that needs an **explicit**
`docs-website/sidebars.js` entry and does not add one, then:

- Medium: doc may publish but never appear in nav.
- Title: "Missing sidebars.js entry"
- Apply to feature guides and similar hand-listed paths.
- Do **not** flag:
  - `docs/generated/`
  - dirs covered by sidebar `autogenerated` entries (e.g.
    `docs/actions/{actions,events,sources,guides}`,
    `docs/generated/ingestion/sources`, metamodel entities)
  - WIP / excluded trees (`docs/wip/`, mostly-unused `docs/what/` stubs)
  - files already ignored by `generateDocsDir.ts`

If a DataHub Cloud release note is added under
`docs/managed-datahub/release-notes/` without being the first entry under
"DataHub Cloud Release History" in `docs-website/sidebars.js`, then:

- Flag: release note won't show in sidebar (newer releases go at the top).
