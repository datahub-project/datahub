**Evidence boundary:** master/PR outcomes are source predictions or explicitly unverified. No master/PR receiver was deployed. Current-branch outcomes come from the [focused Java suites](openlineage-goal-progress-2026-09-30.md), [40 observed smoke passes and two stale-assertion failures](openlineage-goal-progress-2026-09-30.md), and the linked persisted probes. A current local fix does not imply the same bug exists upstream: several native projections are absent there. Each B row links an ordered [payload fixture](openlineage-known-bug-evidence/README.md); the [validation report](openlineage-known-bug-evidence/fixture-validation.json) identifies the captured or legacy requests outside strict 1.53 and distinguishes unexecuted reconstructions. The [crosswalk JSON](openlineage-known-bug-crosswalk-2026-09-30.json) names the exact existing test method or saved live request sequence **and a requested upstream action** for each B ID; test methods are executable repros, while a checked-in assertion alone is not a captured runtime result. The [historical B1–B34 index](openlineage-known-bug-history-index-2026-10-01.json) pins each original decision file at git revision `04e48fb3c7c84a2e6efbe36486f0d12acc37a341`; recover one with the listed `git show` command. Historical acceptance is not current readback proof.

The table answers three separate questions for each B ID. **Yes — bug** means the particular failure is source-predicted or observed. **Yes — support gap** means the target lacks the projection or rejects the event, so the _exact_ local failure cannot occur there; users still lose the stated capability. **No** is limited to the cited path and evidence. **Unverified** names a missing target-matched check. **Outside 1.53** is a compatibility issue, not a strict 1.53 defect. Upstream verdicts are source assessments because master and PR-head services were not deployed. The stack column is the cumulative [#19800 tip](openlineage-goal-2026-10-01.snapshot.json); the [machine matrix](openlineage-known-bug-head-matrix-2026-10-01.json) gives each intermediate head. Each trigger can be reproduced with the exact test method or saved request sequence in the [crosswalk](openlineage-known-bug-crosswalk-2026-09-30.json).

## What the PR authors can act on now

The [core/semantic audit](openlineage-153-core-semantic-target-audit-2026-10-01.md) and [facet audit](openlineage-153-facet-target-audit-2026-10-01.md) give the broader 1.53 gaps. The clearest **newly reachable but incomplete** paths are #18175 job tags/owners without producer-scoped replacement, #19734 dataset tags/owners and selected metrics/lifecycle/storage without complete state semantics, and #19736 DatasetEvent acceptance without lifecycle operation, column lineage, or explicit lineage projection. The clearest **inherited** issues are partial RunEvent I/O loss, optional-metadata identity drift, dataset host collisions, missing explicit LineageFacet, and wrong parent-job identity. The short [six-gap dossiers](openlineage-153-spec-gaps-pr-stack-2026-09-29.md) include schema-valid multi-event reproductions and expected/predicted results. #19740/#19800 need persisted and read-API evidence beyond async acceptance and converter goldens. Do not present these source predictions as observed PR-head failures.

The two smoke failures are test-policy mismatches for B13/B14 under the current branch mapping. The local live probes verify their later replacement/authority sequences, but the existing smoke file still has the earlier expectations. No product code, repository tests, PR comments or tickets were changed for this audit.
