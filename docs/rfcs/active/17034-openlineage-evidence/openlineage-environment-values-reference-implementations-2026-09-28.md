# OpenLineage environment values: reference implementations

Source audit on 2026-09-28. The receiver paths below were traced from HTTP ingestion through mapping and database writes; these are source findings, not live round-trip tests. Public repositories were refreshed through the librarian cache and read without edits. OpenLineage's official facet/configuration pages were also checked.

## Conclusion

The inspected references do **not** establish blanket receiver redaction as an OpenLineage requirement. Marquez preserves supplied environment values. OpenLineage's Python and Spark producers make collection configurable by variable name and transmit the selected values. Airflow applies its existing selective secret masker before emission. OpenMetadata and upstream DataHub omit the facet from their supported persistence mappings, which demonstrates a support gap, not a redaction policy. The pinned [1.53.0 schema](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/spec/facets/EnvironmentVariablesRunFacet.json#L6-L19) defines name/value strings and contains no redaction directive; the [official facet guide](https://openlineage.io/docs/spec/facets/run-facets/environment_variables/) describes runtime configuration values.

For this implementation, preserving received values by default is consistent with the schema and Marquez. Receiver redaction can be a separately specified, opt-in follow-up. This recommendation is an inference from the references and the project's spec-first requirement, not a claim that the specification forbids producer masking.

## Receiver: Marquez

Pinned `MarquezProject/marquez:main` at `180f37b22387146187af1ef0279e3ee1d1ccd789`.

- The [HTTP resource](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/api/OpenLineageResource.java#L65-L76) passes the deserialized event to the service. Unknown run facets, including `environmentVariables`, retain their arbitrary JSON values through [RunFacet's any-setter/getter](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/service/models/LineageEvent.java#L89-L107).
- The service [serializes the complete event](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/service/OpenLineageService.java#L122-L141) through [writeValueAsString](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/db/OpenLineageDao.java#L1152-L1161) into the [`lineage_events.event` SQL column](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/db/OpenLineageDao.java#L90-L108).
- It also [inserts individual run facets](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/db/RunFacetsDao.java#L92-L128) into `run_facets`. This path only excludes `spark_unknown` and deduplicates `spark.logicalPlan`; all other facet JSON is passed through [FacetUtils](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/db/FacetUtils.java#L15-L24). The [facet endpoint](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/api/src/main/java/marquez/api/JobResource.java#L280-L301) returns the stored run facets.

**Finding:** supplied environment value strings survive both persistence paths; no environment-specific mask or receiver option intervenes in these inspected paths. JSON serialization can change representation, so this is value preservation, not byte-for-byte retention.

## Producer: OpenLineage Python client

Pinned release `1.53.0` at `48302e12018aea164bd903283b6841a939d8ef1f`.

[`facets.environment_variables` defaults to an empty list](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/client/python/src/openlineage/client/facets.py#L18-L21). The client [collects only configured names from `os.environ`, copies their values, and preserves event-supplied values when merging](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/client/python/src/openlineage/client/client.py#L462-L518). The [HTTP transport serializes that event into the POST body](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/client/python/src/openlineage/client/transport/http.py#L382-L401). The [official configuration guide](https://openlineage.io/docs/client/python/configuration/#facets) describes this opt-in name selection and merge behavior.

**Finding:** opt-in collection by name; no blanket masking of collected or supplied values in this client path.

## Producer: OpenLineage Spark

Pinned release `1.53.0` at the same OpenLineage commit. The inspected environment capture files are unchanged between this release and refreshed `main` (`d204b0e1be9040d3f39474fe257ae103842e811d`).

Spark reads [`facets.custom_environment_variables`](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/client/java/src/main/java/io/openlineage/client/transports/FacetsConfig.java#L33-L40) into the [emitter's optional variable list](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/integration/spark/app/src/main/java/io/openlineage/spark/agent/EventEmitter.java#L62-L69). Its [builder copies configured `System.getenv()` values](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/integration/spark/shared/src/main/java/io/openlineage/spark/agent/facets/builder/CustomEnvironmentFacetBuilder.java#L30-L47); the Java [HTTP transport sends the serialized event](https://github.com/OpenLineage/OpenLineage/blob/48302e12018aea164bd903283b6841a939d8ef1f/client/java/src/main/java/io/openlineage/client/transports/HttpTransport.java#L311-L331).

**Finding:** configurable name selection and value preservation for the custom `environment-properties` facet. This is **not** the standard `EnvironmentVariablesRunFacet`, so it is supporting evidence about producer policy, not proof of that standard facet's Spark behavior. Databricks has a separate environment builder; it was not audited here.

## Producer: Apache Airflow

Pinned refreshed `apache/airflow:main` at `acaa1cba93083a47849071e1b2412f03732f9945` (read directly from the fetched ref; the cached worktree was not advanced).

The provider [creates an OpenLineageRedactor from Airflow's current SecretsMasker](https://github.com/apache/airflow/blob/acaa1cba93083a47849071e1b2412f03732f9945/providers/openlineage/src/airflow/providers/openlineage/plugins/adapter.py#L82-L87), [redacts the event](https://github.com/apache/airflow/blob/acaa1cba93083a47849071e1b2412f03732f9945/providers/openlineage/src/airflow/providers/openlineage/plugins/adapter.py#L164-L173), then [calls the Python client's emit](https://github.com/apache/airflow/blob/acaa1cba93083a47849071e1b2412f03732f9945/providers/openlineage/src/airflow/providers/openlineage/plugins/adapter.py#L201-L205). Its [redactor inherits existing patterns and sensitive-field settings](https://github.com/apache/airflow/blob/acaa1cba93083a47849071e1b2412f03732f9945/providers/openlineage/src/airflow/providers/openlineage/utils/utils.py#L1977-L2026); the underlying masker [replaces matching secret strings and otherwise returns them unchanged](https://github.com/apache/airflow/blob/acaa1cba93083a47849071e1b2412f03732f9945/shared/secrets_masker/src/airflow_shared/secrets_masker/secrets_masker.py#L416-L423).

**Finding:** selective producer masking is present by default in the adapter; it does not blank every environment value. Environment collection configured in the Python client occurs inside `client.emit`, after adapter masking, so the adapter alone does not establish that all client-added environment values are masked. Exact results depend on the deployed client version and Airflow's registered secrets/settings.
