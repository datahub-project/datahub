SearchTemplate

A Mustache-rendered search query template, addressed by URN and selected at query time. Managed through the generic entity API. Not included in default search, browse, or autocomplete entity-type lists. import Tabs from '@theme/Tabs'; import TabItem from '@theme/TabItem';

Technical Reference Guide​

The sections above provide an overview of how to use this entity. The following sections provide detailed technical information about how metadata is stored and represented in DataHub.

Aspects are the individual pieces of metadata that can be attached to an entity. Each aspect contains specific information (like ownership, tags, or properties) and is stored as a separate record, allowing for flexible and incremental metadata updates.

Relationships show how this entity connects to other entities in the metadata graph. These connections are derived from the fields within each aspect and form the foundation of DataHub's knowledge graph.

Reading the Field Tables​

Each aspect's field table includes an Annotations column that provides additional metadata about how fields are used:

  • ⚠️ Deprecated: This field is deprecated and may be removed in a future version. Check the description for the recommended alternative
  • Searchable: This field is indexed and can be searched in DataHub's search interface
  • Searchable (fieldname): When the field name in parentheses is shown, it indicates the field is indexed under a different name in the search index. For example, dashboardTool is indexed as tool
  • → RelationshipName: This field creates a relationship to another entity. The arrow indicates this field contains a reference (URN) to another entity, and the name indicates the type of relationship (e.g., → Contains, → OwnedBy)

Fields with complex types (like Edge, AuditStamp) link to their definitions in the Common Types section below.

Aspects​

searchTemplateProperties​

Python class: SearchTemplatePropertiesClass

A Mustache-rendered search query template. Sections that are unset are inherited from {@code parent}. An explicitly present empty string for {@code query}, {@code clauses}, {@code functionScore}, {@code rescore}, {@code knn}, or {@code ladder} drops that inherited section. An explicitly present empty {@code ranking} or {@code retrieval} drops that inherited section. An explicitly present empty {@code fields}, {@code highlightFields}, {@code aggregations}, or {@code sort} drops the inherited override and falls back to the schema or Java default. An explicitly present empty {@code boosts} drops an inherited list. An explicitly present empty {@code structuredPropertyQuery} drops an inherited section. A child replaces only the structured-property clauses it sets. An explicitly present empty {@code normalization} drops inherited query-normalization settings. A child replaces only the normalization fields it sets. Each non-empty {@code queryFragments} value adds to the root-first comma join for that hole. An empty string drops inherited pieces for that hole. {@code routes} is replaced as a whole list: unset keeps the parent list, an empty list drops it, and a non-empty list replaces it. {@code defaultRoute} is inherited on its own. Unset keeps the parent default. A record with a template replaces it. A record with no template clears it.

{@code apiVersion} is the template and Mustache-context contract. Unset keeps the parent version. When no ancestor sets it, the resolved version is 1. A value other than 1 is rejected when the template is written and when it is loaded. An accepted write stores 1 when the caller omits it. {@code capabilities} names features this body requires. Unset keeps the parent list. An empty list drops it. A non-empty list replaces it. A name this release does not implement is rejected when the template is written and when it is loaded.

{@code dialect}, {@code apiVersion}, {@code parent}, and {@code editable} are searchable with {@code queryByDefault} false. A write uses {@code parent} to find its children; the other fields support template administration filters. {@code aspectJson} stores this aspect's JSON, the same JSON stored in SQL, at {@code _aspects.searchTemplateProperties._aspectJson} without indexing it, so a template reload can read the body from search. Write time and actor stay on system metadata ({@code aspectCreated}, {@code aspectModified}): SQL stores them on the aspect row, and search copies them to {@code _system}. The entity stays out of the default search, browse, and autocomplete entity-type lists.
