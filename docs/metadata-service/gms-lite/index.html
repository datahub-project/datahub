GMS lite

Run the production war.war locally without Docker, Kafka, or a database server. Requires Python 3.10+, a POSIX system (Linux or macOS), and JDK 25. Python uses only the standard library. The first Gradle build downloads JVM dependencies.

export JAVA_HOME=~/.local/share/mise/installs/java/25.0.2
python3 metadata-service/gms-lite/bin/gms-lite-stack.py

The launcher builds the GMS and upgrade jars plus the embedded OpenSearch installDist, gets or starts the shared OpenSearch node, then runs datahub-upgrade.jar -u SystemUpdate and -u RestoreIndices for each new instance. Upgrade processes run serially to limit memory use. GMS processes start after bootstrap finishes. Readiness requires HTTP health and, when authentication is enabled, the bootstrap user's policies.

Use --skip-build after building those artifacts. --heap 1g sets each GMS/upgrade heap cap. One OpenSearch JVM per major, with a 4 GB default heap, serves local stacks using that major. Set EMBEDDED_OPENSEARCH_HEAP when building its distribution to change that cap, then stop and start the shared node to apply it:

EMBEDDED_OPENSEARCH_HEAP=6g ./gradlew :metadata-service:opensearch-embedded:installDist
python3 metadata-service/gms-lite/bin/_opensearch_manager.py stop
python3 metadata-service/gms-lite/bin/_opensearch_manager.py start

Select the engine with --opensearch 2|3 on either Python entry point, EMBEDDED_OPENSEARCH_VERSION=2|3, or -PopensearchVersion=2|3 when building with Gradle (the Gradle property takes precedence over the environment). The single default is embeddedOpenSearchDefault=3 in the root gradle.properties, matching the Docker compose and head quickstart default (OpenSearch 3.7). The no-version quickstart still pins v1.9.0, which runs 2.19. The embedded runner is 2.19.1.0 for major 2 and 3.7.0.0 for major 3. Both include their matching custom-codecs plugin; -Pknn or OPENSEARCH_KNN_ENABLED=true adds the matching k-NN plugin at build time. Plugin extraction uses Sync in per-major directories. Both majors' dependencies and plugin archives are always locked, independently of selection and k-NN. To refresh this module's lockfile:

./gradlew :metadata-service:opensearch-embedded:resolveAndLockAllForProject --write-locks

run, classes, and installDist select the requested major. Distributions live under metadata-service/opensearch-embedded/build/install/opensearch-embedded-os<major>/, so building one major preserves the other. test runs testOs2 and testOs3, compiling the shared tests and lifecycle code separately against each server.

The launcher records the major in <data-dir>/opensearch-major and publishes opensearchVersion in stack.json. Warm starts retain the recorded major; changing it requires --fresh. Existing stacks without a major are treated as 3. The manager records and checks data-directory ownership by major and refuses ~/.datahub/local/opensearch/, which belongs to another tool. Nodes of both majors may run together on separate ephemeral ports.

GMS and upgrade processes use these settings from the selected configuration:

MajorELASTICSEARCH_SHIM_ENGINE_TYPEELASTICSEARCH_SHIM_AUTO_DETECTELASTICSEARCH_INDEX_DOC_IDS_SCHEMA_FIELD_HASH_ID_ENABLED
2OPENSEARCH_2falsefalse
3OPENSEARCH_3falsetrue

Both explicit engine types are supported by the search shim. Auto-detection is unnecessary because the launcher starts a known engine. Keeping schema-field ID hashing disabled on 2 preserves Docker 2.x document-ID compatibility. On 3, hashing avoids the 512-byte bulk document-ID limit and retains existing IDs. These settings apply to bootstrap and GMS alike.

The shared node keeps its data, logs, port, pid, and startup.lock under ~/.datahub/local/opensearch-<major>/ (opensearch-2/ or opensearch-3/). These directories separate major versions because OpenSearch data directories are not portable across major versions. Override it with --shared-opensearch-dir /path/to/state on the launcher or GMS_LITE_OPENSEARCH_DIR for both entry points. Manager commands accept --dir /path/to/state. Always use the same directory to manage a node.

The manager serializes start/stop with an exclusive file lock, verifies process identity before signalling, and reuses only a healthy node of the selected major. A dead node or a verified node whose connection is refused is replaced while retaining its data; a different major version or an unrelated PID is refused. For a live node, readiness waits up to 600 seconds for yellow health. Override this with GMS_LITE_OPENSEARCH_HEALTH_TIMEOUT_SECONDS. An unresponsive or slow node that reaches the deadline causes a clear error and is left running, with its recorded PID and port unchanged. This also applies to a newly started node: once it reports READY, its port is recorded before waiting for yellow. Retry start to reuse it and wait again. A child that exits, fails to report READY within 900 seconds, or reports the wrong major version is stopped and its PID/port files are removed. Interrupting startup also cleans up the new child; an already running node being reused is left alone. Data is always retained; choose a different state directory or repair the data explicitly if it cannot recover. status snapshots PID/port under the lock, then probes outside it with one-second HTTP timeouts and no readiness wait. It returns JSON with healthy: false and a short reason for a red, paused, unreachable, or incompatible node. There is no automatic deletion of other stacks' indices.

Both HTTP and transport ports are ephemeral. Use --private-opensearch for a node owned by this stack, with data under <data-dir>/opensearch-<major>/, that stops with the launcher. Supplying --opensearch-port N also selects private mode (0 means ephemeral); occupied ports are refused. Private mode is useful for CI and self-contained runs.

python3 metadata-service/gms-lite/bin/gms-lite-stack.py \
  --skip-build --data-dir /tmp/my-gms --port-base 18090 --processes 2

--processes defaults to 1. Instances are named gms-0, gms-1, etc. Each has its own H2 file, queue spool, object-storage directory, HTTP port, and index prefix. Prefixes include a hash of the absolute data-directory path and the instance name, avoiding collisions between identically named directories. Instances share one OpenSearch node but never an index. By default the shared node runs in its own session and outlives every launcher that uses it; stopping one stack leaves other stacks running. The launcher prints the command to stop the shared node:

python3 metadata-service/gms-lite/bin/_opensearch_manager.py status
python3 metadata-service/gms-lite/bin/_opensearch_manager.py stop

Stopping the shared node interrupts search for every stack using it. Stop stacks first. The manager sends SIGTERM, waits for shutdown, and uses SIGKILL only if necessary. start can also prewarm the node without starting GMS.

Service values live in layered env files. env/common is followed by env/docker-free, extension layers, and the optional --job folder. --mode local|ci selects variant files. Repeatable --env-file [scope:]PATH applies ad-hoc overrides last. The launcher then protects isolated storage, search and auth connections. --print-env boots nothing and prints redacted values with their source; every start writes the same report to <data-dir>/resolved-env.json. The generated gms-N/env.sh records settings that differ from the inherited environment, using shell-safe quoting. It is an output file and is never read back automatically.

Discovery and authentication​

Once ready, <data-dir>/stack.json is published atomically, with mode 0600:

{
  "bootId": "unique-random-id-for-this-start",
  "opensearchVersion": "2",
  "opensearchPort": 54321,
  "opensearchShared": true,
  "default": "gms-0",
  "instances": {
    "gms-0": "http://localhost:18090",
    "gms-1": "http://localhost:18091"
  },
  "indexPrefixes": {
    "gms-0": "gmslite0123456789abgms0",
    "gms-1": "gmslite0123456789abgms1"
  },
  "auth": true,
  "frontendPort": 19002,
  "systemClientId": "__datahub_system",
  "systemClientSecret": "<system-client-secret>",
  "adminTokens": {
    "gms-0": "<personal-access-token>",
    "gms-1": "<personal-access-token>"
  },
  "adminTokenExpiresAt": {
    "gms-0": "2026-01-02T12:00:00Z",
    "gms-1": "2026-01-02T12:00:01Z"
  }
}

opensearchShared says whether stopping this launcher leaves the node running. default is a key in instances. indexPrefixes contains the configured INDEX_PREFIX values; GMS appends an underscore before index names. bootId changes on every start. adminTokens contains a one-day personal token for the existing bootstrap user datahub in each instance. adminTokenExpiresAt maps the same instance names to the server-issued token expiry in ISO-8601 UTC. After expiry, authenticated requests return 401 even if /health still succeeds. Restart the stack with the same data directory to mint new tokens, then reread stack.json; tokens are not refreshed while the launcher runs. The launcher uses OSS's shipped bootstrap policies without adding or replacing any policy.

--frontend-port publishes frontendPort (otherwise null). With authentication enabled, systemClientId and systemClientSecret let Vite's lite mode verify native credentials and mint browser sessions through the same GMS auth APIs as Play; both are null with --no-auth. These fields are private, like adminTokens. The launcher itself does not start a frontend; scripts/dev/datahub-dev.sh start --local starts and manages Vite.

Pass the instance token as Authorization: Bearer <token>, or use it with the DataHub CLI as DATAHUB_GMS_TOKEN alongside DATAHUB_GMS_URL. /health and /config are public. For example:

curl -fsS http://localhost:18090/health
curl -fsS http://localhost:18090/config

--no-auth disables token authentication and publishes auth: false with empty adminTokens and adminTokenExpiresAt objects. GMS binds to loopback. The system credentials and token keys are randomly generated, saved in <data-dir>/.secrets.json with mode 0600, and reused on restart. Neither credentials nor tokens are printed to stdout.

Persistence and recovery​

Stop with Ctrl-C or SIGTERM to the launcher PID. It stops GMS and active upgrade processes, waits for JVM shutdown, and kills remaining children in their owned process groups if they do not exit. Shared OpenSearch stays up. In private mode, GMS stops before the owned OpenSearch node. The spool is saved during orderly JVM shutdown; SIGKILL or power loss can lose queued events. This is a local development stack.

Restart with the same absolute data-directory path. H2, search indices, credentials, and queue snapshots persist. A gms-N/system-update-done marker is written only after both upgrade commands succeed; it records the instance's non-usage-event index names observed at that point. Existing H2 tables are never recreated on a retry. Upgrades are skipped only when H2 exists, this marker contains a nonempty recorded index set, and every recorded index still exists. If any recorded index is missing, both upgrades run again to restore search from H2. The usage-event index is ensured separately on every start. Older text markers trigger one upgrade run to record the set. Remove the marker to rerun upgrades after changing bootstrap code.

An exclusive lock prevents concurrent launchers from using the same data directory, including with --fresh. Old stack.json files are removed under that lock before startup; the discovery file is removed again on exit. --fresh clears only a directory previously marked as belonging to this launcher (or an empty directory). With shared OpenSearch it also deletes the exact index prefixes of this stack's current and previously persisted instances, followed by _, including matching aliases, data streams, and templates. Names are enumerated before deletion; no wildcard DELETE is sent. Other prefixes are preserved. Without --fresh, the same prefixes and data are reused. Do not move an active data directory or remove its sibling .gms-lite.lock file. The launcher never removes H2/OpenSearch lock files or reclaims other processes' ports. Startup errors retain data and logs for diagnosis.

Usage-event indices use the mappings from the upgrade jar's source template, without ISM lifecycle settings. Automatic usage-event rollover and retention are unavailable on this minimal node. The embedded distribution includes the matching custom-codecs plugin because GMS selects zstd_no_dict for ordinary indices. Semantic search remains disabled by default; the launcher does not request k-NN.

Verification​

./gradlew :metadata-service:gms-lite:check
./gradlew :metadata-ingestion:lintFix
./gradlew :metadata-service:gms-lite:stressTest
# New results directory (previous results are otherwise resumed):
./gradlew :metadata-service:gms-lite:stressTest -PstressDataDir=/tmp/gms-lite-check
# Select cases:
./gradlew :metadata-service:gms-lite:stressTest -PstressTests="persistence parallel stale"
# Or build and verify with a fresh temporary results directory:
metadata-service/gms-lite/bin/verify-stack.sh

launcherSafetyTest runs fast, offline safety tests and is part of check. The module's lint and lintFix Gradle tasks use the repository's pinned Python tool and ruff.toml; check includes lint. A repository pre-commit hook runs the module's lintFix task for Python/config changes.

The opt-in stress suite checks authenticated ingest/read/search, H2 and spool restart persistence, same-PID warm starts, parallel instance isolation, concurrent cold launches of two separate stacks, replacement of dead nodes, timeout without replacement of a paused live node, private-node shutdown, prefix-scoped --fresh, restoration after total or single-core-index loss, SIGTERM during upgrades, closed owned ports, stale discovery recovery, and explicit manager shutdown. It always uses a temporary shared state directory and stops that node in teardown, including after failures. Each case's verdict is appended and flushed immediately to build/stress/results.jsonl. Re-running skips already recorded cases, including failures; use a new --data-dir or remove that results file to rerun them. Results and service logs are retained on failure. Use a port base with two free consecutive ports (default 18090).

tail -f metadata-service/gms-lite/build/stress/results.jsonl
python3 metadata-service/gms-lite/tests/summarize.py \
  metadata-service/gms-lite/build/stress/results.jsonl

Neutralised search overrides​

These values override both the shell and --env-file. Each YAML property is protected by clearing or pinning both its placeholder names and its canonical environment name. Names are generated from the paths below using Spring Boot's environment mapping: replace dots with underscores, remove dashes, uppercase, and surround list indices with underscores. Camel-case words stay joined (e.g. pathPrefix becomes PATHPREFIX). same means the canonical name is already a listed placeholder.

Empty URI values let ElasticSearchConfiguration.normalizeClusters() synthesize the primary URI from the pinned host/port and leave the secondary unconfigured. elasticsearch.host and .port already map to ELASTICSEARCH_HOST and ELASTICSEARCH_PORT, pinned to localhost and the embedded port. Neither the YAML nor SearchClusterSettings defines clusters.primary.host or .port; nested host/port names cannot override the connection. Boolean switches use false; proxy schemes use http.
